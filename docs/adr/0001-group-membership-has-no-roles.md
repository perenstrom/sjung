# Group membership has no roles table

Group membership (`UsersToGroups`) carries no role field. The only privileged position within a Group is the **Creator** — the User recorded in `Group.createdById` — and every permission check that needs "is this user allowed to manage the group" (member management, and future group-wide features like announcements) compares against that id rather than reading a role off the membership row. We chose this over a roles table because Sjung currently has exactly one privilege tier to express (creator vs. everyone else), and a roles table would be pure ceremony until a second tier is actually needed. Introducing real roles later is a real migration — existing guard helpers (`requireCreatorGroupBySlug`, `requireCreatorGroupById` in `lib/actions/guards.ts`) would need to move off `createdById` comparisons onto role lookups.
